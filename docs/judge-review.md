## 2. Top 5 fixes, ranked by score gain per minute

1. **Route every Gemma call through Respan and put the dashboard on the side monitor** (Respan 1 -> 3 or 4; ~15 min). `wordhunt/seats/gemma.py` and `integrations/commentator.py` already take `base_url` / `api_key`; set `GEMMA_BASE_URL=https://api.respan.ai/api` (or the gateway's OpenAI-compatible path) with `GEMMA_API_KEY=$RESPAN_API_KEY` and the model routed to the Lambda vLLM endpoint as a Respan custom provider; if the gateway refuses an arbitrary vLLM URL, wrap the two `urllib` calls with the Respan tracing SDK instead (PLAN.md §5 fallback). Then change the seat label in `wordhunt/seats/registry.py` from `gemma · text grid` to `gemma 12B · Lambda · via Respan`, and have a browser tab with the Respan trace list open on the side monitor before the round starts. A parallel worker is on this; the on-screen label and the open dashboard tab are the part that scores.
2. **One env change on the Cloud Run revision once the Lambda vLLM box is up**: `GEMMA_SEATS='[{"id":"gemma-12b","name":"Gemma 12B","model":"google/gemma-4-12B-it","base_url":"<respan-or-lambda>","api_key":"..."}]'` and `WH_SEATS=nano,gemma-12b,reflex-a` in `scripts/deploy.sh` (Lambda 2 -> 4, bonus 0 -> 1, multi-agent 4 -> 5 by having three kinds of bot on the board; ~10 min after the box is reachable). This makes Gemma a first-class `ai` seat with a `label` and the `stats` block (calls, latency, tokens, traceable) on the projector, instead of the Mac bot masquerading as a human. Do it on a new tag (`deploy.sh iter5`), rehearse one round, then promote.
3. **Land the Lambda-trained nano and say so on screen** (Lambda 2 -> 3; ~10 min once training stops at ~2:35): commit `nano/checkpoints/<best>.pt` + `nano/results/<gate>.md`, set `NANO_CKPT` in `deploy.sh`, change the nano `label` in `wordhunt/seats/registry.py` to `10M · trained on Lambda A100 · $0 · ~2 ms`, and replace the "placeholder" paragraph in `docs/architecture.md` §3 with the real numbers (steps, wall time, val metrics, gate vs `d6_s0`). If the Lambda checkpoint does not beat `d6_s0` on the gate, ship `d6_s0` and still write the comparison: "we tried d8 and long-word weighting on an A100; here is why we kept d6" is a legitimate "compare approaches" answer.
4. **Make the Nango tool call visible without a terminal** (Nango 3 -> 4; ~10 min): in `integrations/commentator.py` prefix the model's text with `Gemma 12B (via Nango tool call):` so the Discord post itself is the proof, start the commentator (`python -m integrations.commentator --room CODE --server https://<demo-host>`) before the round, and have the Discord channel open in a second projector tab so the post lands live at the buzzer. If there is time, one more action is worth more than threads: file each Gemma `miss` as a second Nango action (Linear issue "CTA is not a word") through the same `tools.TOOLS` list, so the model chooses between two tools.
5. **Record the 3-minute backup video now and post it in Discord** (protects every line above; ~15 min, one take, phone camera on the projector is fine). Sponsor judges who are not at your table score from the recording. Without it a Lambda box that goes down at 4:25 zeroes 02 and the bonus. The script below is the take.

Not worth the minutes before 4:30: wiring `nano/learn.py` into the rematch countdown (30+ min, touches `wordhunt/room.py` and the seat cache, and a bad rollback on stage is worse than not having it). Say it exists, cite the measured curve, show `nano/results/live_learning_curve.png` if asked.

### Q&A cheat sheet (2 minutes, likely questions)

| Question | Answer (numbers from `main`) |
|---|---|
| Why a nano instead of just Gemma? | Gemma 12B cannot trace adjacency: 80% of its output is real English not on the board (364 "not on board" vs 44 "not a word" in the 20-board text run); 20% valid, 2.1 s per call. The nano only moves to adjacent tiles by construction, 96-97% valid, decides in ~2 ms on a Mac / 19 ms on one Cloud Run vCPU. Gemma is the teacher and the comparison; the nano is what a phone can run. |
| What is fine-tuned? | Nothing on Gemma: LoRA was deliberately cut (PLAN.md §10; prior GUI-LoRA runs were inside seed noise). The nano is trained from scratch: 11.0M params, depth 6, d_model 384, 200k self-solved boards -> 4.96M samples, 17.3k steps x 256 in a 30-minute budget, soft-CE on next-tile and action type plus BCE on a value head. The Lambda run adds d8 and long-word weighting with bf16 + compile (state the result if it landed). |
| How is Lambda used? | A100 for the nano training sweep today (four trainers, 33-minute budget), and (if up) vLLM serving Gemma 4 12B to the registry seat inside Cloud Run. Inference for the nano is CPU in the game process; no GPU at serve time. |
| How is Respan used? | AI gateway in front of every Gemma call (seat and commentator): traces, latency, tokens, cost per word, and the side-by-side of the seat variants. Nano calls are local so they are not traced; that is the point of the $0 row. |
| How is Nango used? | One Discord integration (`discord-wordhunt`), one custom action (`send-discord-recap`). Server fires it on room created / round started / round ended. At the buzzer Gemma is given that action as an OpenAI tool and calls it itself (`integrations/commentator.py`); template fallback only if the model does not call the tool within 10 s, and that fallback is logged, not hidden. |
| Cost? | Nano: $0 per match, 44 MB checkpoint, in-process. Gemma 12B: about 12 calls x ~200 tokens per 75 s race; on Lambda that is a fraction of a cent per match at A100 hourly rates, quote the Respan number if the dashboard shows it. Training: 30 min MPS for `d6_s0`; the Lambda sweep was capped at $40. |
| Latency? | Nano 1.9 ms per action (Mac), 19 ms on the 1 vCPU Cloud Run shape, at a 10 Hz hand so it never waits. Gemma 12B 2.1 s mean per call, p50 1.8 s, streamed so the finger starts on the first line. Server tick 20 Hz. |
| Multiplayer scale? | One Cloud Run instance (1 vCPU, 1 GiB), session affinity, rooms in memory; 24 humans and 6 AI seats per room by cap; unbounded rooms per instance until CPU runs out. Horizontal scale needs sticky rooms per instance or a shared store, not built. |
| Does it learn live? | The learner exists and is measured (`nano/learn.py`: 50 BC steps in 9-10 s on CPU, 8/10 updates kept, recall of taught words 35% -> 46%, held-out flat). It is not wired into the rematch countdown yet; be exact: "it learns the words it was just shown; it does not get better at Word Hunt in ten rounds." |
| Why does the Gemma bot show as a human? | The Mac-side bot joins over the same WebSocket a phone uses. The registry seat (`wordhunt/seats/gemma.py`) is the proper `ai` seat; it needs an endpoint reachable from GCP, which is the Lambda box. |
| Can humans win? | Yes, by tuning: Nano think 1.5-3 s and Reflex 5-13 s were set so a decent human beats them on rich boards (`tuning` in `/api/health`). Say it: the pace is a knob, and the untuned nano scores 9,126 a board. |

## 4. Commercial viability (VC voice)

The thesis is on-policy distillation of frontier AI agents into tiny, task-specialized action models: frontier teacher -> tiny policy, same environment, same actions, same clock (today's 11M model is trained from self-solved trajectories; closing the teacher loop is the next step). Word Hunt VS is a wedge into that: a spectatable arena where humans, a frontier open model, and a distilled 11M-parameter student play the same board under the same physical constraints, and every round produces a labelled comparison (valid rate, latency, tokens, cost, word length) that a benchmark table cannot fake. The game is the acquisition channel and the ground truth; the eval harness and the distillation recipe (big open model as teacher, tiny on-device policy as the product) are the business. It fits an "open source, small models, hybrid compute" thesis exactly: the money is not in the game, it is in being the place where teams find out whether their small model actually plays like a person before they put it on a device.

- **Model:** free-to-play arenas as the top of funnel; paid eval seats for model teams (bring your endpoint, get a human-calibrated score, traces, and cost per action across boards and games); a distillation service that trains the nano-sized policy from a customer's teacher model and ships it as a checkpoint.
- **Expansion:** every casual game with a fixed rule set (word games, match-3, trivia) is a new arena and a new benchmark; game studios pay for believable bots that play at human pace, which is exactly the hand controller.
- **Moat:** the human comparison data. Every human round is a labelled sample of "what does human pace look like on this board," and that is the dataset nobody else is collecting.

**Sharpest objection:** "This is a word game with bots; eval harnesses do not monetise and casual games do not need a VC." **Rebuttal:** the game is not the product, the paired measurement is. The league table already shows the thing model teams cannot get from static benchmarks: a 12B model with 20% valid words and a 10M model at 96%, on the same boards, under the same 75 s clock, with humans as the bar. Small-model teams shipping to phones need exactly this comparison before they ship, and today they run it by hand. The game is how you get the humans for free.
